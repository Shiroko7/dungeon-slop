## Storage and compatibility

- SQLite is canonical. Schema v5 adds a dungeon revision and mutation receipts;
  it preserves existing maps, descriptions and blueprints.
- Back up the SQLite database with the application stopped before upgrading.
  No migration has been run against the developer's real campaign database.
- PATCH dungeon now takes `{ expectedRevision, operationId, patch }`. Room-note
  PUT/DELETE also require a revision and UUID operation ID. Fork requests require
  the parent's revision. Blind writes from an old frontend are rejected.
- Creating/finding the Architect thread uses POST, not a state-changing GET.
- A matching receipt returns the originally acknowledged revision even if another
  writer has since committed. Approximately 1,000 recent receipts per dungeon are
  retained; older ambiguous retries conflict rather than overwrite newer data.
- Browser recovery stores only unacknowledged operations. It is bounded to 4 MiB
  and 20 pending maps per origin, and never evicts another pending copy.
- Browser Web Locks prevent taking over a recovery copy still owned by another
  tab. Recovery checks existence and revision, and cannot recreate deleted owners.
- Recovery is browser/profile/origin-local. Clearing site data removes it. A storage
  denial, quota error or oversized map remains visibly unsafe until the server
  acknowledges it; keep that tab open or export its local copy. This is not a
  guarantee against every browser or OS crash.
- Conflict resolution shows the current server content. Keeping local edits is a
  deliberate field-level replacement, not an automatic merge. Reload/discard asks
  for confirmation; export the local copy first when needed.
- The JSON recovery download is an inspectable safety copy, not a general project
  import format. A project backup/import workflow remains M3.

## Local API boundary

Default listener: `127.0.0.1:3000`. Vite proxies to that IPv4 loopback address.
Browser mutations accept the local API origin and Vite on port 5173, using
`localhost`, `127.0.0.1`, or `[::1]`. Other hostnames/origins are rejected.
CLI requests without Origin still work; this is not authentication.

Intentional non-loopback serving requires both `API_HOST` and explicit
comma-separated `ALLOWED_ORIGINS`, including the address actually used by clients.
Do not expose this unauthenticated app to an untrusted network. For example,
`API_HOST=0.0.0.0` and `ALLOWED_ORIGINS=http://192.168.1.20:3000` is an explicit
trusted-LAN choice, not a supported hosted deployment.

Cancelling generation aborts downstream consumption and propagates an abort signal
to Claude, Gemini and Ollama requests. Work already performed may still be charged;
cancellation does not guarantee a refund or immediate cessation at the provider.

## Verification

Automated regressions exercise reversed owner loads, late room descriptions,
same-owner edits invalidating older AI results, both Architect cancellation phases,
save coalescing and ordering, failed/lost acknowledgements, independent dungeons,
reload recovery, deleted owners, two-writer conflicts, storage failure/budgets,
recovery locks, malformed/misowned API requests, origin checks, stream cancellation,
and preservation across the v4-to-v5 migration.

Run without touching real campaign data (PowerShell):

```powershell
$env:NOTES_DB_PATH = ':memory:'
bun test
bun x tsc --noEmit
bun run build
```

The actual OS listener was checked using an isolated in-memory server on port
33007: only `127.0.0.1` was listening and health returned OK.
